## 1. DASH 加速系統

### 1.0 設計理念 (白話解釋)
> 「讓大蛇不再無敵。在傳統規則中，大蛇可以靠長度無限衝刺，對小蛇極度不公。
> 
> 在這個版本中，當你身體越長，加速的代價就會像滾雪球一樣快速變大。如果你變成一條巨蛇，加速一秒鐘可能會讓你瞬間縮水掉原本長度的一大半。
> 
> 此外，**加速消耗的長度有 60% 會掉落在蛇尾**。這意味著大蛇衝刺時會沿路灑下大量寶藏，這讓後方的追擊者（小蛇）有機會一邊追擊一邊進食，進而反超大蛇。
> 
> 這保證了不論蛇多大，衝刺爆發都只能維持**短短幾秒**。大蛇必須精準算計每一秒的衝刺時機，否則會迅速散盡長度，這讓小蛇有了透過靈活操作反殺大蛇的公平競技空間。」

### 1.1 核心算法 (The Formula)
每秒消耗的長度值 ($Cost$) 應由以下公式計算：
$$Cost = R_0 \times \left[ 1 + \left( \frac{L - L_{min}}{K} \right)^2 \right]$$

- **資源回饋 (Drop Rate)**：DASH 總消耗長度的 **60%** 必須轉換為食物掉落在蛇尾。

### 1.2 建議實作參數
| 參數符號 | 參數名稱 | 建議數值 | 說明 |
| :--- | :--- | :--- | :--- |
| **$R_0$** | Base Drain Rate | **40** | 當長度等於初始長度時的基礎消耗速度 (units/sec) |
| **$L_{min}$** | Min Length | **50** | 初始長度，長度低於此值時停止加速 |
| **$K$** | Scaling Constant | **100** | 控制曲線斜率的常數，數值越小，大蛇消耗越劇烈 |

### 1.3 預期行為與數據對照 (二次方模型 $K=100$)
透過此模型，衝刺總時長存在一個物理極限（約 **3.92 秒**），長度再大也無法超越。

| 目前長度 | 起始消耗速率 (u/s) | 衝刺總時長 (至 50 為止) | 備註 |
| :--- | :--- | :--- | :--- |
| **50** | 40 | 0s | 初始長度不可衝刺 |
| **100** | 50 | **~1.15s** | 與線性模型體感接近 |
| **200** | 130 | **~2.45s** | 成長回報開始大幅放緩 |
| **300** | 290 | **~2.97s** | 雖然長度翻倍，但時長增加不到 0.6s |
| **500** | 850 | **~3.37s** | 消耗極其劇烈，適合瞬間突擊 |
| **1000** | 3650 | **~3.66s** | **時長進入高原期** |
| **10,000** | 396,040 | **~3.91s** | **物理極限，無法突破 4s** |

## 2. 死亡與資源循環 (Corpse Mechanics)
- **回饋比例**：總長度的 **80%**。
- **存在時間**：**5.0 秒**。
- **邏輯說明**：高價值屍體誘導玩家近身博弈，短時間消失防止地圖資源過剩。

## 3. 競技數據指標定義 (Stats)
| 指標名稱 | 程式內部變數 | 定義 |
| :--- | :--- | :--- |
| **TOTAL SCORE** | `totalEaten` | 整場比賽累計吃掉的食物總分 (勝負唯一依據) |
| **KILLS** | `kills` | 對手頭部碰撞導致的死亡次數 |
| **CUTS** | `cuts` | 衝刺時成功攔腰切斷對手的次數 |
| **DEATHS** | `deaths` | 自身死亡次數 |
| **DASH TIME** | `totalDashTime`| 累計衝刺總秒數 |
