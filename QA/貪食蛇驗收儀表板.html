GDD 是驗收條件真源；Notion 是交付範圍與時程來源，不表示 QA 通過。背景 runner 只驗證 cc-free 裁判層；UI、動畫、輸入與實機操作仍需另行填寫正式案例。

開啟最新版 GDD ｜ 開啟 Snake Schedule

  1. 先對齊交付資料：讀取 Snake Schedule 後更新本輪快照，再執行 npm run qa:publish-notion。正式 runner 僅接受 5 分鐘內、且具 DoD／build／測試入口的快照；前置阻塞只新增 run 證據，不會覆蓋最後有效的 qa-latest-run.js。背景診斷另寫入 diagnostic 資料源。
  2. 記錄外包提交的版本號、Cocos 版本、平台、裝置與測試帳號；在儀表板用篩選選擇本輪 Stage。
  3. 先執行該 Stage 的進入／建置／資源載入煙霧測試；只要無法進局、崩潰、資料毀損或核心分數錯誤，即提 P0／P1。
  4. 逐項填寫「通過／不通過／未執行」、證據與備註；缺少測試條件等阻塞原因保留在證據與下一步，不另立容易混淆的結果狀態。
  5. 失敗時從案例建立 Bug，補齊重現步驟、預期、實際、Log／影片與影響範圍；修正後將 Bug 置為「待回歸」。
  6. 匯出 JSON 作為本輪證據。當必測項已執行、P0/P1=0、P2 均修正或被明確豁免、規格待確認有裁定時，才標示 Stage Gate 通過。
