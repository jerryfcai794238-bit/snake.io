# Workflow: Plan

## 觸發

- Level 2／3 修改，或使用者主動要求規劃。
- 小型 hotfix 仍屬 Level 2，可縮短 Plan，但不可跳過「開始」。
- Level 0／1 不需 Plan。

## 流程

1. **研究**
   - 唯讀搜尋目標、規格、相依與工作區狀態。
   - 確認現況、真源、風險與未知事項，不為規劃寫檔。
2. **分級**
   - 判定 Level 2／3，列出連動文件、備份需求、回滾方式及不可逆影響。
3. **顯示 Plan**
   - 依 [工具轉接規則](../rules/agent_safe_rules.md) 使用目前工具的原生載體。
   - 包含目標、影響範圍、步驟、備份、驗證、不做事項。
4. **核准**
   - 只接受使用者在 Chat 明確回覆「開始」。
5. **執行**
   - 先備份，再按核准範圍做最小修改與驗證。
   - 範圍或架構改變時停止，更新 Plan 並重新等待「開始」。
6. **完成**
   - 回報修改檔案／章節、重點、驗證、備份與未驗證事項。

## 跨工具

只有使用者明確要求切換工具時，依工具轉接規則建立 `scratch/handoffs/current.md`；一般任務不建立 Plan 或 handoff 檔。
