# GDD 反向同步與代碼校準協議 (GDD Reverse Sync Policy)

本文件定義 GDD 與實際程式碼實作之間進行雙向同步與校準的流程，確保「規格」與「代碼」100% 一致。

## 1. 觸發校準時機 (Triggers)
- **版本發布前**：執行 `/release` 或提交 Commit 前，必須進行代碼反向比對。
- **重構與重度修改後**：完成核心演算法（如 AI 決策路徑、碰撞判定、積分換算）修改後。
- **使用者要求**：使用者請求「核對規格與實作是否吻合」時。

## 2. 審查與同步對象 (Target Code Files)
進行同步時，必須人工或透過工具核對以下核心程式碼檔案中的數值與變數定義：
- **全域常數定義**：如 `src/constants.js` 或配置檔。檢查數值是否與 GDD 參數總覽表完全一致。
- **物理與動作邏輯**：如 `src/snake.js` 或 `src/controllers/` 中的基礎速度加算公式、衝刺體力扣除率、重生幽靈時間門檻。
- **地圖與生成邏輯**：如 `src/game.js` 或地圖控制器。核對初始食物積分（如 3000 分）、補足下限（如 1000 分）、地圖寬高、河流緩速百分比等。

## 3. 同步校準標準 (Sync Standards)
- **實作優先原則**：若代碼已在測試中運行良好且符合玩法需求，但 GDD 描述的數值不同（例如因開發過程微調），**必須將 GDD 更新為代碼中的實際數值**。
- **同步表格化**：所有從程式碼同步回文檔的配置常數，必須在 GDD 的「第 4 章：參數表總覽」中以 Markdown 表格形式呈現。
- **缺口稽核 (Gap Audit)**：同步完成後，應執行專案內部的 Gap 稽核流程（如 `/gap-audit`），比對當前代碼、GDD 與使用者最原始需求，確認無漏掉或衝突的規格。
