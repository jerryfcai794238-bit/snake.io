# GDD 規格保全協議 (GDD Spec Preservation Protocol)

為了防止 GDD 在頻繁的迭代進版中因 Agent 覆寫而發生「內容閹割」、「規格降級」或「細節丟失」，必須嚴格遵守此保全協議。

## 1. 編輯前強制讀取 (Context Reading Requirement)
- **拒絕摘要更新**：在修改 GDD 之前，必須完整讀取待修改章節的前後上下文，確保對該章節的既有設計有全局理解。
- **結構完整性檢查**：在寫入更新前，比對舊有標題與結構，確認新版本中沒有漏掉任何一個二級或三級標題及其對應的規格說明。

## 2. 核心組件鎖定 (Component Lockdown)
以下內容為 GDD 的核心實作基準，除非「該功能模組被使用者明確要求刪除」，否則**嚴禁簡化、概括或刪除**：
- **數值參數表**：所有物理常數、時間常數、百分比係數的 Markdown 表格。
- **操作交互規範**：按鍵映射、搖桿操作、按鈕 CD 扇形冷卻與倒數遮罩的視覺規格。
- **UI 像素與參數**：明確定義的座標系、解析度規格、像素大小 (px) 以及放大比例。
- **邊界與限制判定**：如邊界碰撞扣減長度百分比、無敵時間限制等特殊規則。

## 3. 進版合併與過時機制處理 (Merge & Legacy Rules)
- **增量寫入**：新規則與新參數應優先作為「補充條款」或「參數表追加行」寫入，避免直接刪除舊邏輯。
- **過時機制標記**：若舊有機制被全新玩法取代，應採取以下兩種方式之一處理：
  1. 在舊描述處加上 `[已於 vX.X 更新為 XXX，詳見第 X.X 節]`。
  2. 將舊機制完整剪下，移至文檔末尾的 `## 附錄：過時/歷史機制 (Legacy Mechanics)` 存檔，以供日後追溯。

## 4. 自動稽核與 Walkthrough 核對
在每次完成 GDD 更新後，所產出的 `walkthrough.md` 報告中，必須自我核對並列出：
- [ ] 是否完整繼承並保留了所有未被刪除的舊有數值表格？
- [ ] 新舊版本的文件大小 (Bytes) 與總行數 (Lines) 的對比（需顯式列出數字）。
