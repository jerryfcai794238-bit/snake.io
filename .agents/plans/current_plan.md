# 工作規範整理 Plan

## 目標
把本專案目前的工作流程整理成可複製到其他專案的標準規範，並修正本檔案的亂碼問題，讓後續每次修改前都能先建立 plan、先給使用者確認、再開始動檔。

## 等待確認狀態
- 狀態：等待確認
- 只有使用者明確回覆 `開始` 後，才可以進行正式檔案修改

## 預計修改檔案
```text
.agents/plans/current_plan.md
```

## 預計步驟
1. 先整理並確認規範內容，將目前 workflow 轉成可複製的標準模板。
2. 修正 `current_plan.md` 的亂碼與編碼問題，確保內容可正常閱讀。
3. 補入備份與清理規則：
   - 修改規格、GDD、美術需求、字串表、參數表、版本紀錄前先備份
   - 備份位置固定為 `scratch/backups/YYYYMMDD_HHMMSS/<original-path>`
   - 只保留最近一次版本更新日往前 3 天內的備份
   - 例如今天是 `6/17`，若今天有更新版本，則可刪除 `6/14` 以前的備份，只保留 `6/15`、`6/16` 的備份
4. 補入修改前後的流程：
   - 先建立或更新 plan
   - 先讓使用者檢查
   - 使用者回覆 `開始` 後才動檔
   - 完成後回報改動章節、備份位置與未驗證事項
5. 補入驗證規則：
   - 檢查關鍵字
   - 檢查 Markdown 表格
   - 檢查圖片路徑
   - 檢查 `<details>` 是否平衡
   - 檢查版本號一致性
6. 完成後回報本次整理內容與影響範圍，等待下一步指示。

## 預期輸出
- 一份可正常閱讀、無亂碼的 plan 檔
- 一套可搬到其他專案的標準工作流程
- 明確的備份保留規則與回報規則

## 可能影響範圍
- `.agents/plans/current_plan.md` 的內容與格式
- 未來在此專案內進行規格、GDD、美術需求、字串表、參數表、版本紀錄時的工作方式
- 備份清理規則與保留週期

## 規範摘要
- 每次開始正式修改前，先更新 `current_plan.md`
- 先讓使用者確認 plan，使用者回覆 `開始` 後才可以動檔
- 修改規格、GDD、美術需求、字串表、參數表、版本紀錄前，先備份到 `scratch/backups/YYYYMMDD_HHMMSS/<original-path>`
- 只改指定檔案與指定章節，不順手擴大修改
- 若發現會連動其他文件，先寫進 plan 或先回報，不可直接擴改
- 完成後必須回報修改檔案、完成重點、備份位置與未驗證事項
- 備份只保留最近一次版本更新日往前 3 天內的檔案，超出者可清理
