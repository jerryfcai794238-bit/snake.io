# GDD 撰寫標準規範 (GDD Writing Standards)

為了確保 GDD 具備最高等級的精確度與可讀性，Agent 產出 GDD 時必須嚴格遵守以下標準：

## 1. 表格化優先 (Table-Driven)
- **數值必表**：所有物理參數、冷卻時間、距離、機率、配額等「數值型」資料，嚴禁使用段落描述，必須使用 Markdown 表格。
- **邏輯必表**：狀態切換（如碰撞矩陣）、技能效果對比、導引條件等「邏輯型」資料，必須以表格呈現。

## 2. 漸進式結構 (Progressive Structure)
GDD 的章節順序必須遵循「基礎核心 -> 增益模組」的漸進邏輯：
1. **環境規格 (Environment)**：基礎物理空間、地圖尺寸、格線。
2. **核心系統 (Stamina/Dash)**：體力消耗、恢復、基礎加速操控。
3. **戰術技能 (Tactical Skills)**：主動觸發的 CD 技能。
4. **戰鬥矩陣 (Combat Matrix)**：碰撞勝負判定、受傷、死亡惩罰。
5. **視覺回饋 (UI/VFX)**：介面標記、指引、特效演出。
6. **增益模組 (Extra Systems)**：隨機道具、動態投放、行動導引（如 Adaptive Ecosystem）。

## 3. 實作級細節 (Implementation-Level Details)
- **禁止模糊描述**：嚴禁使用「效果顯著」、「速度提升」等模糊字眼。
- **邏輯透明化**：必須寫出底層邏輯，例如「以 25px/s 吸往蛇頭」、「免疫截斷改為回彈」、「R=400 範圍」。

## 4. 規格繼承與保全 (Spec Persistence)
- **全量讀取**：更新 GDD 前必須完整讀取舊版。
- **禁止閹割**：新版 GDD 必須完整繼承舊版的所有數值表格，除非該功能被明確刪除。

## 5. 反向同步校準 (Reverse Sync)
- **實現代碼核對**：進版前必須核對 `src/constants.js` 與 `src/game.js` 的實際變量，確保 GDD 數據與現有代碼 100% 吻合。

---
*違反此標準導致 GDD 內容模糊或細節丟失，視為任務失敗。*
