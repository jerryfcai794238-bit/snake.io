# 驗證與回報規則

本檔集中定義完成前驗證與回報格式。出現阻塞時依 [偏離與失敗處理規則](failure_handling.md) 執行。

## 一般驗證

- 優先執行既有測試、語法、建置或 Lint。
- 沒有自動化時，至少檢查 Markdown 標題、內部連結、表格、圖片路徑、`details`、Mermaid 與必要關鍵字。
- Agent 規則修改後，必須檢查：目標 rules 存在、`AGENTS.md` 連結有效、舊檔名引用處理完畢、關鍵規則可搜尋命中。

## GDD／GDK 驗證

- GDD／GDK 任務依 [GDD／GDK Agent 規則](gdd_agent_rules.md) 的完成驗證執行。
- 若只做稽核，回報差異與證據，不自動修正。
- 若發現需修改文件、GDK 或程式，另依 [Plan 與核准規則](plan_and_approval_rules.md) 取得有效核准。

## Prototype／程式驗證

- Prototype 優先驗證可啟動、可操作、可觀察結果。
- 程式修改優先跑既有測試、語法檢查、建置、Lint 或最接近的本地檢查。
- 若工具因環境限制失敗，標記為「未完成驗證」，並說明最接近的替代檢查。

## 完成回報

完成後回報必須包含：

- 修改檔案與章節。
- 完成重點。
- 驗證結果。
- 備份位置。
- 未驗證事項或限制。

不得在未完成驗證前宣稱完成、通過或已修好。
