# 編輯、備份與版本規則

本檔集中定義寫檔範圍、備份、版本與磁碟真源規則。Plan 與核准依 [Plan 與核准規則](plan_and_approval_rules.md) 執行。

## 磁碟真源

- 磁碟現況是真源；讀取實際檔案後再判斷，不以記憶或先前回報取代現況。
- 保留既有未提交變更，不使用 reset、checkout 或清理命令覆蓋它。
- 只修改核准檔案與範圍；發現連動文件時先列明，不順手擴大。

## 備份規則

- 修改 GDD、GDK、規格、美術需求、音效需求、字串表、參數表、版本紀錄、Agent 規則或其他高影響文件前，備份至 `scratch/backups/YYYYMMDD_HHMMSS/<original-path>`。
- 備份必須保留原始相對路徑，方便還原與比對。
- 備份與跨工具交接資料只留本機，不提交 Git。
- 若需要清理備份，必須先取得使用者明確指示。

## 版本規則

- 只有使用者明確要求推版、版更或標記版本時，才更新文件版本、日期、版本紀錄、頁尾標記或 Git Tag。
- 不因一般內容修改自動推版。
- 若版本規則與任務目標衝突，先回報並等待使用者決定。

## 寫檔方式

- 優先使用目前工具的標準安全寫檔能力。
- 若已知目前環境的標準寫檔路徑會被 Windows 沙箱阻擋，依 [偏離與失敗處理規則](failure_handling.md) 使用核准後的低風險 fallback。
- 寫檔後必須依 [驗證與回報規則](verification_reporting.md) 做最小必要驗證。
