# GDD 規格保全協議 (GDD Spec Preservation Protocol)

為了防止 GDD 在進版過程中發生「內容閹割」或「細節丟失」，所有 Agent 必須嚴格遵守以下保全協議：

## 1. 編輯前強制讀取 (Full Context Requirement)
- **嚴禁摘要式更新**：在更新 GDD 之前，必須使用 `view_file` 讀取當前版本的所有內容。
- **結構比對**：必須列出當前版本的所有一級與二級標題，確保新版本中這些標題（或其對應的邏輯）依然存在。

## 2. 核心組件鎖定 (Component Lockdown)
以下內容除非「功能被完全刪除」，否則**禁止簡化或刪除**：
- **數值矩陣 (Tables)**：任何關於碰撞邏輯、技能參數、數值平衡的 Markdown 表格。
- **操控規範 (Controls)**：按鍵綁定（Keybinds）、靈敏度參數、操控邏輯描述。
- **UI 參數 (UI Specs)**：具體的像素值（px）、顏色代碼（Hex）、縮放比例（Scale）。
- **死亡/復活規則**：具體的惩罰百分比、冷卻時間、安全區域距離。

## 3. 進版合併規則 (Merge Logic)
- **增量優先**：新功能應作為「新增章節」或「現有章節的補充」加入，而非覆蓋掉整段舊有描述。
- **過時標註**：若某項舊機制被新機制取代，應將舊描述移動至 `## 附錄：過時機制 (Legacy Mechanics)` 或在原處加上 `[已於 vX.X.X 更新為 XXX]`，而非直接刪除。

## 4. 自我審計要求 (Self-Audit)
在完成 GDD 更新後的 `walkthrough.md` 中，必須包含以下核查：
- [ ] 是否保留了所有舊有的數值表格？
- [ ] 是否保留了所有按鍵綁定說明？
- [ ] 新舊版本的文件大小（Bytes）與行數（Lines）比對說明。

---
*此協議為最高優先級，違反此協議視為任務失敗。*
