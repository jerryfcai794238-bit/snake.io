# Plan 與核准規則

本檔集中定義任務分級、Plan 展示、有效核准、不同 IDE／Agent 工具的 Plan 顯示方式，以及跨工具交接。這些規則集中維護，避免跨檔重複。

## 任務分級

- **Level 0／回答**：不讀檔、不修改；不需 Plan。
- **Level 1／唯讀調查**：可搜尋、讀取、分析與驗證；不需 Plan 或核准。
- **Level 2／可逆修改**：單一文件、少量檔案、局部程式碼、局部 GDD／GDK 或 prototype 修改。
- **Level 3／高影響修改**：跨模組、批次、刪除、搬移、架構、核心規格、Agent 規則、推版、版本異動或不可逆操作。

## Plan 展示

- Level 2／3 必須先唯讀研究，再向使用者展示可見 Plan。
- 只要任務需要 Plan，就必須展示給使用者，不得只在內部規劃後自行執行。
- Plan 至少包含：目標、影響範圍、步驟、備份、驗證、不做事項。
- 一般任務不建立 `current_plan.md`、`implementation_plan.md`、`task.md` 或替代 Plan 檔。
- 若任務進入新階段且會產生新影響範圍，例如「prototype 實驗 → GDD 同步」或「稽核 → 修正」，必須再次展示階段 Plan，或明確列出下一步影響範圍、產出檔案、備份與驗證方式。

## 建議與執行分離

- 稽核、檢視或討論中發現可改善項時，必須明確標示「這是建議，尚未執行」。
- 若改善涉及 Level 2／3 寫檔，必須提出 Plan 並等待有效核准；不得直接修改。
- 若使用者問「要不要」、「可不可以」、「為什麼不」等決策問題，先回答判斷與規則歸屬，再詢問是否要進入 Plan。

## 有效核准

有效核准有兩種等價來源，任一成立即視為使用者已同意執行目前 Plan：

1. **Plan UI 核准**：使用者點擊與目前 Plan 綁定、語意明確表示執行該方案的 UI 選項，例如「是，實做此方案」、「是，實作此方案」、「接受並開始實作」或「開始製作」。
2. **聊天核准**：使用者在聊天中明確回覆 **「開始」**，或明確要求執行已展示且未變更的 Plan。

核准判定規則：

- 先檢查是否已有與目前 Plan 綁定且語意明確的 Plan UI 核准；若有，必須直接開始執行，不得再要求使用者額外輸入「開始」。
- 單獨的 Accept、OK、可以、confirm、approved 或一般肯定，若未明確表示執行目前 Plan，仍不算有效核准。
- 收到有效核准後才能寫檔。
- 若目標、範圍、架構、產出檔案或風險實質改變，原核准失效；必須停止、更新 Plan 並重新取得有效核准。
- 小型 hotfix 可使用精簡 Plan，但不能略過核准。

## IDE / Agent 工具 Plan 顯示

- **Antigravity**：使用原生 Artifact／Planning UI 顯示 Plan，並在對話中提示使用者檢視。
- **VSCode Codex**：優先使用擴充套件的 Plan Mode／Plan UI；若目前版本沒有原生 Plan UI，降級為 Chat 內的 `## 計畫` Markdown 區塊。
- **Codex App**：優先產出使用者可見、可在右側檢視並可點擊「是，實作此方案」等核准按鈕的方案卡／Proposal；不得把內部工作 checklist 或僅供 Agent 狀態追蹤的 plan 當成已展示 Plan。
- 若目前工具無法產出方案卡／Proposal，或使用者明確表示看不到右側 Plan，必須立即降級為 Chat 內的 `## 計畫` Markdown 區塊，並明確說明「方案卡未出現，改用 Chat 可見 Plan」。
- 若 UI 文案不清楚、未綁定目前 Plan、使用者看不到 Plan，或無法判斷是否表示開始實作，必須回到聊天要求明確核准。
- 不得為了呈現 Plan 而建立專案內的替代 Plan 檔。

## 跨工具交接

只有使用者明確要求切換工具時，才建立或更新 `scratch/handoffs/current.md`。該資料夾應留在本機，不提交 Git。

交接檔固定包含：

1. 來源工具、目標工具與更新時間。
2. 任務目標與已核准範圍。
3. 有效核准狀態、核准方式與對應 Plan。
4. 已完成項目與已修改檔案。
5. 備份位置與驗證結果。
6. 未完成項目、已知問題與禁止擴大範圍。

接手工具必須先讀取 `AGENTS.md`、handoff、實際檔案與工作區差異：

- 範圍未變且 handoff 明確記錄已收到有效核准：可續做未完成項目。
- 範圍、架構或目標改變：原核准失效；重新展示 Plan 並取得新的有效核准。
- 不重做已完成項目，不把 handoff 當成取代磁碟現況的真源。
