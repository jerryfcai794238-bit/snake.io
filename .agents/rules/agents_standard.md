# AGENTS.md 加強版模板

這份檔案設計成可直接複製到其他專案使用，再依專案特性微調。

## 1. 全域共用規則

### 回覆風格
- 一律以繁體中文回覆，除非使用者另有要求。
- 風格簡潔、直接、以結果為先。
- 把使用者當成專業協作者。
- 有風險、限制或不確定性時直接說清楚。

### 任務分級與工作節奏
- **Level 0／回答**：不讀檔、不修改；直接回答，不需 Plan。
- **Level 1／唯讀調查**：可讀檔、搜尋、分析與整理；直接執行，不需 Plan 或核准。
- **Level 2／可逆修改**：使用 Codex 內建 Plan UI 展示計畫，等待使用者明確回覆「開始」後修改。
- **Level 3／高影響修改**：使用內建 Plan UI 展示詳細計畫、風險與回滾方式，等待使用者明確回覆「開始」後修改。

唯一有效核准詞為「開始」。其他肯定語句或實作要求均不等同核准。

### Plan 規範
- Plan 的唯一真源是目前 thread 的 Codex 內建 Plan UI。
- 不建立 current_plan.md、implementation_plan.md、task.md 或其他 Plan 文件。
- Plan 至少包含目標、影響範圍、執行步驟、備份策略、驗證方式與不做事項。
- 唯讀探索可在 Plan 前或規劃期間執行。
- 需求或影響範圍實質改變時，更新內建 Plan 並重新等待「開始」。

### 修改原則
- 先讀上下文，再動手。
- 只改指定檔案與指定章節，不順手擴大修改。
- 若需要同步其他文件，先列入內建 Plan 或回報，不可默默一起改。
- 工作跑偏時立刻停止，提供保留、還原或暫放；還原前先備份目前狀態。

## 2. 專案版規則

### 修改前備份
- 修改規格、GDD、美術需求、字串表、參數表、版本紀錄前，先備份。
- 備份位置固定為 scratch/backups/YYYYMMDD_HHMMSS/<original-path>。
- 修改前只備份，不先改內容。

### 備份清理
- 只保留最近一次版本更新日往前 3 天內的備份檔。
- 判定基準以最近更新版本日期為準，不只看檔案建立時間。
- 未明確要求推版或清理時，不主動刪除備份。

### 文件同步檢查
修改規格、GDD、美術需求、字串表、參數表、版本紀錄時，需同步檢查：
- 規則與 UI 文案。
- 圖片引用。
- Icon、Map、FX、SFX。
- 參數與版本號。

### 版本紀錄
- 只有使用者明確要求推版或版更時才更新。
- 推版時同步更新文件版本、更新日期、版本紀錄與頁尾版本標記。

### 驗證與回報
- 修改後檢查關鍵字、Markdown 表格、圖片路徑、details 標籤平衡與版本號一致性。
- 完成後回報修改檔案、修改章節、完成重點、備份位置與未驗證事項。

## 3. 可選擴充

可依專案補充命名規則、素材管理、外包交付、版本格式及 GDD／規格／美術需求／字串表對照規則。
