# AGENTS.md 加強版模板

這份檔案設計成可直接複製到其他專案使用，再依專案特性微調。

## 1. 全域共用規則

### 回覆風格
- 一律以繁體中文回覆，除非使用者另有要求。
- 風格簡潔、直接、以結果為先。
- 把使用者當成專業協作者，不要講廢話。
- 如果有風險、限制、或不確定性，直接講清楚。

### 工作節奏
1. 每次開始實作前，先建立或更新 `.agents/plans/current_plan.md`。
2. 先讓使用者檢查 plan。
3. 使用者明確回覆 `開始` 後，才可以修改檔案。
4. 完成後要回報：
   - 修改了哪些檔案
   - 修改了哪些章節
   - 完成重點
   - 備份位置
   - 未驗證事項

### 修改原則
- 先讀上下文，再動手。
- 只改指定檔案與指定章節，不順手擴大修改。
- 如果發現需要同步其他文件，先寫進 plan 或先回報，不可默默一起改。
- 如果工作跑偏，立刻停下來，先說明情況，再決定保留、還原或暫放。

## 2. 專案版規則

### Plan 檔規範
- `.agents/plans/current_plan.md` 必須是可讀的 UTF-8 純文字。
- 若發現亂碼、編碼損壞、不可讀內容，先視為 plan 損壞問題處理。
- Plan 內容至少包含：
  - 目標
  - 等待確認狀態
  - 預計修改檔案
  - 預計步驟
  - 預期輸出
  - 可能影響範圍

### 修改前備份
- 修改規格、GDD、美術需求、字串表、參數表、版本紀錄前，先備份。
- 備份位置固定為：
  - `scratch/backups/YYYYMMDD_HHMMSS/<original-path>`
- 修改前只備份，不先改內容。
- 若發現有連動文件，先列入 plan 再處理。

### 備份清理規則
- 只保留最近一次版本更新日往前 3 天內的備份檔。
- 例如今天是 `6/17`，且今天有更新版本，則可刪除 `6/14` 以前的備份，只保留 `6/15`、`6/16` 的備份。
- 判定基準以「最近更新版本日期」為準，不只看檔案建立時間。

### 文件同步檢查
修改規格、GDD、美術需求、字串表、參數表、版本紀錄時，需同步檢查：
- 規則是否一致
- UI 文案是否一致
- 圖片引用是否一致
- Icon、Map、FX、SFX 是否衝突
- 參數與版本號是否衝突

### 版本紀錄規則
- 只有在使用者明確要求推版或版更時，才更新版本紀錄。
- 推版時需同步更新：
  - 文件版本
  - 更新日期
  - 版本紀錄
  - 頁尾版本標記

### 驗證規則
修改後要檢查：
- 關鍵字
- Markdown 表格
- 圖片路徑
- `<details>` 是否平衡
- 版本號是否一致

### 回報格式
完成後固定回報：
- 修改檔案
- 完成重點
- 備份位置
- 未驗證事項

## 3. 可選擴充區

這一區放專案專屬規則，其他專案可視情況增減。

### 可補充項目
- 特定檔案的命名規則
- 圖片與素材管理規則
- 外包交付格式
- 版本號格式
- 文案審核流程
- GDD / 規格 / 美術需求 / 字串表之間的對照規則

## 4. 建議使用方式

如果要把這份模板搬到新專案，建議保留以下結構：
1. 全域共用規則
2. 專案版規則
3. 可選擴充區

這樣可以讓每個新專案只需要補自己的特殊規則，不用整份重寫。
