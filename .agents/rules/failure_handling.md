# 偏離與失敗處理規則

本檔定義 Agent 卡住、跑偏、工具失敗、驗證阻塞、Windows 沙箱與權限問題時的處理方式。

## 快速判斷

- **跑偏**：工作開始修改未核准範圍、引入無關重構、產出與目標不符，或讀寫資料明顯超出任務需要。
- **卡住**：同一問題反覆搜尋、重試、補救或驗證，仍沒有讓任務更接近完成。
- **工具阻塞**：命令、patch、轉檔、渲染、測試或外部工具因環境、權限、Temp、沙箱、檔案鎖定而失敗。
- **高風險補救**：刪除、搬移、大量覆寫、重建檔案、變更架構、安裝套件、修改全域環境。

## 60 秒換路徑規則

- 任一單一步驟執行超過 60 秒仍未完成時，必須終止該步驟，回報目前狀態，並改用已知低風險替代路徑；若沒有明確替代路徑，立即熔斷。
- 同一任務階段的連續補救、重試、替代命令或驗證迴圈，累計超過 60 秒仍未解除同一阻塞時，視同逾時。
- 不得以多個短命令、反覆讀相同資料、改寫 Plan 或重做同一檢查來規避 60 秒限制。
- 等待使用者核准、使用者回覆或外部事件，不計入 60 秒執行時間。

## 補救上限

- 同一失敗原因最多允許 2 次補救嘗試。
- 第 1 次補救：改用最小、低風險、可解釋的替代方法。
- 第 2 次補救仍失敗：停止自動操作並熔斷回報。
- 驗證工具因環境、權限、Temp 目錄、沙箱或外部工具限制失敗時，最多只做 1 次明確、低風險的環境修正後重試；仍失敗就標記為「未完成驗證」。

## 已核准小修快速路徑

- 當使用者已明確核准 Level 2／3 的局部規則修正，且修改檔案與內容方向已在前文確認時，Agent 不得再次完整重讀所有相關 rules。
- 只允許做最小必要確認：備份目標檔、讀取即將修改的目標片段、直接套用修改、立即驗證。
- 若目前環境已知 `.agents` 寫入需要 fallback，應直接走已核准 fallback，不先嘗試標準寫入或重複鋪陳。
- 快速路徑不得擴大目標、加入新規則重構、搬移檔案或刪除未核准內容。

## Windows / Codex 寫檔阻擋

- 在 Windows PowerShell 讀取繁中 rules、GDD、GDK 或其他 Markdown 規格時，必須明確使用 UTF-8，例如 `Get-Content -Encoding utf8`；不得用預設編碼讀取後依亂碼內容判斷規則。
- 若目前環境已知 `apply_patch` 會因 Windows sandbox wrapper、split writable root、restricted-token 或類似問題失敗，不得反覆嘗試已知必敗路徑。
- 在已展示 Plan、已取得有效核准、已完成必要備份，且修改範圍明確限縮時，可直接使用低風險 PowerShell fallback 寫入核准檔案；PowerShell 讀寫必須明確指定 UTF-8。
- fallback 只能修改核准範圍；不得趁機擴大重構、搬移或刪除未核准檔案。
- fallback 後必須做唯讀驗證，確認檔案存在、UTF-8 讀取正常、內容命中關鍵規則、內部連結有效。

## Patch fallback 執行流程

前置條件：

1. 已展示 Plan。
2. 已取得有效核准。
3. 已完成必要備份。
4. 修改範圍明確限於核准檔案。

執行規則：

- 可使用 UTF-8 patch 暫存於 `scratch/`，或使用低風險 PowerShell 寫入核准檔案；所有讀取、比對與寫入都必須明確使用 UTF-8。
- 每批操作不得超過 Codex CLI patch 上限 24,000 字元；超限時先按檔案、再按獨立 hunk 拆分。
- 每批操作成功後立即唯讀驗證目標內容。
- 任一批失敗即停止，保留已成功批次並回報狀態。
- 不得趁 fallback 擴大重構、搬移或刪除未核准檔案。
- 全部完成後執行任務原定的同步、語法、測試或文件驗證。

## 1385 權限錯誤

- 在 Windows 環境下，VSCode Codex 的標準沙箱程序啟動路徑已知可能觸發 `CreateProcessWithLogonW 1385`；不得先嘗試該路徑。
- VSCode Codex 命令執行必須直接使用工具提供的沙箱外執行／權限核准機制。
- VSCode Codex 寫檔不調用原生 `apply_patch`；必須建立 UTF-8 patch 至 `scratch/`，並透過沙箱外執行／權限核准機制執行 fallback 腳本。
- Antigravity 預設優先使用原生高效工具，不受 VSCode Codex 的預防性禁用限制。
- 若任何 Agent 在執行過程中意外觸發 `1385`，最多僅允許嘗試 1 次 fallback；若 fallback 失敗或再度觸發 `1385`，必須熔斷。

## Patch 與檔案修改

- Codex CLI 單批 patch 上限為 24,000 字元；超限時先按檔案、再按獨立 hunk 拆分。
- 每批 patch 成功後立即做唯讀驗證。
- 任一批 patch 失敗時先確認是否可用同一工具修正；若同一原因第 2 次失敗，停止並回報。

## 熔斷回報

熔斷時必須停止擴大修改，並回報：已完成內容、已修改或產出的檔案、失敗步驟與已知原因、未完成驗證、可行後續處理方式。

若已產出或修改檔案，必須提供三種選項：

- **保留**：維持目前檔案，等待後續指示。
- **還原**：先備份目前狀態，再還原至上次備份或修改前狀態。
- **暫放**：保留檔案但不再擴大修改，改由使用者手動檢查或指定下一步。

未取得使用者選擇前，不得擴大修改。
