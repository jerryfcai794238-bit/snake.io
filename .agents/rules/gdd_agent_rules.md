# GDD／GDK Agent 規則

本檔是本專案 GDD 與 GDK／DataTable 的唯一領域規則。通用 Plan、核准、備份、版本、Windows fallback 依其他 rules 執行，不在本檔重複。

## 適用範圍

- 撰寫、修改、稽核或同步 GDD。
- 建立、修改、稽核 GDK／DataTable、參數表、字串表關聯與企劃資料表。
- 比對 GDD、程式、資源、UI 文案、Icon、Map、FX、SFX、GDK 或其他指定真源。

## 小任務快速路徑

- 小型 GDD 文案、標題、格式、錯字或局部表格修正，只讀任務必要上下文。
- 小任務不強制比對所有程式、UI、Icon、Map、FX、SFX、GDK 與資源；僅檢查目標章節與受影響元素。
- 若小修過程發現可能牽動規格、數值、資料表、資源綁定或版本資訊，停止快速路徑並回到一般 GDD 任務流程。

## GDD 任務流程

1. 先讀取目標章節及前後上下文，記錄原有二、三級標題、數值表、圖片與特殊標記。
2. 依任務範圍比對相關程式、控制器、UI、資源、GDK 與其他實際來源。
3. 來源衝突時停止擴大修改，列出衝突值、檔案與章節，等待使用者指定真源。
4. 只修改 Plan 核准章節，不用摘要覆蓋完整規格。
5. 未定義或無法證實的數值不得自行補造；確認後的配置維持單一真源並以表格呈現。
6. 稽核只產出差異報告；修正文件或程式需另依 Plan 核准範圍執行。

## GDD 編輯保全

- 除非使用者明確要求刪除功能，禁止簡化或移除：數值參數表、操作映射、UI 像素／比例、狀態邊界與限制條件。
- 新規則優先增量補充；舊機制被取代時，標記替代版本與新章節，或移至文件內的歷史機制附錄。
- 文件或核心邏輯異動需同步檢查規則、UI 文案、圖片、Icon、Map、FX、SFX、參數與版本是否衝突。

## GDD 表格化標準

- **數值必表**：物理參數、冷卻時間、距離、機率、配額、屬性明細等，必須整理成 Markdown 表格。
- **邏輯必表**：狀態機切換、碰撞矩陣、技能效果、道具覆蓋規則等，以表格呈現。
- 數值參數表必須包含：`參數名稱`、`參數描述`、`預設數值/初始數值`、`滿級數值`（若有）、`每級增量`（若有）、`單位`。

## GDD 數值標準

- GDD 參數一律採無小數點整數設計。
- 比例／機率使用萬分比整數，例如 `50%` 寫為 `5000`，`1.35 倍` 寫為 `13500`。
- 亞秒或帶小數秒數換算為毫秒，例如 `2.5 秒` 寫為 `2500ms`；整數秒可維持 `s`。
- 物理距離與速度使用 `px` 或 `px/s`。

## CJK LaTeX 渲染保全

- 含中文字元或文字說明的公式，禁止使用 LaTeX／KaTeX 區塊。
- 公式與計算式改用標準純文字程式碼區塊。

```text
升級所需金幣 = PASSIVE_UPGRADE_BASE_COST * (PASSIVE_UPGRADE_EXPONENT / 100) ^ 當前屬性等級
```

## GDD 章節架構

GDD 主體章節優先遵循由底層到上層的漸進邏輯：

1. 角色基礎屬性。
2. 地圖與環境。
3. 食物與生成。
4. 復活與生命週期。
5. 競技模式與 AI。
6. 技能與道具。
7. 養成與經濟。
8. UI 與美術需求。

## GDD 版本與標記

- 只有使用者明確要求推版或版更時，才更新文件版本、更新日期、變更紀錄與頁尾版本標記。
- 行內版本標記只標示本次新增或修改內容；標題與 Mermaid 內容不得加入標記。
- 進版時清除舊版行內標記，保留最新版本；目前版本的 `details` 可展開，歷史版本預設折疊。
- Mermaid 節點有括號或特殊字元時，使用雙引號包住整段文字。

## GDK 基本定位

- GDK 是供企劃維護、程式匯入的遊戲資料，不是資料庫 Schema。
- 依 GDD、參數表、美術需求、字串表與其他指定規格建立資料。
- 不自行加入 PK、Index、Auto-Inc、VARCHAR、UNSIGNED 等資料庫設計。
- 不虛構來源文件未定義的價格、ID、資源名稱、字串表編號、貨幣或狀態。
- 必要但未定義的欄位保持空白，並在完成回報列為待補資料。

## GDK 表格固定結構

每張表依序包含：

1. A1 表格名稱列。
2. `輸出`。
3. `名稱`。
4. `資料型態`。
5. `企劃名`。
6. 實際資料列。

規則：

- A1 必須填實際表格／檔案名稱，例如 `Module`、`ActiveSkill`。
- 不使用 `Item`、`Table` 等通用占位名稱。
- 每一資料列代表一筆可配置資料。
- 每列欄位數必須一致。

## GDK 輸出與型態

- `B`：Client + Server 共用。
- `C`：僅 Client 使用。
- `S`：僅 Server 使用。
- 純企劃閱讀、描述、單位或備註欄位不輸出。
- 非輸出欄位在 `輸出`、`名稱`、`資料型態` 三列全部留空。
- 輸出欄位必須同時具有輸出標記、程式名稱與資料型態。
- 常用型態限定為 `int`、`string`、`bool`。
- 原則上不使用 `float`；小數時間改用整數秒或毫秒，機率、倍率與速度修正使用百分比或萬分比整數。
- 布林狀態使用 `bool`，資料填 `true`／`false`。

## GDK 字串表、描述與單位

- 中文名稱與描述屬企劃閱讀欄位，不直接輸出。
- 程式需要顯示文字時，新增對應字串表編號欄位。
- 欄位順序必須相鄰：名稱 → 名稱字串表編號；描述 → 描述字串表編號。
- 字串表編號欄位通常使用 `int`；未提供字串表編號時保持空白，不自行編號。
- 描述欄只說明效果與用途，不重複寫百分比、萬分比、秒、毫秒等單位。
- 單位統一放在最後的 `單位` 備註欄；單位欄不輸出，因此不設定程式名稱與資料型態。
- 同一程式欄位不可混用秒與毫秒。
- 比例欄若統一採萬分比，負值也需換算，例如 `-25%` 寫為 `-2500`。

## GDK 拆表與單一真源

- `Module` 僅保存沒有獨立專表管理的全域參數。
- 技能、道具、AI、造型、貼圖等多筆同類資料應各自拆表。
- 所有資料只能有一個真源，專表與 Module 不得重複。
- 建立專表後，只移除真正重複的 Module 參數，不可整類刪除。
- 修改前應逐項確認保留、移除或移轉。
- 所有資料列共用的值應放入 Module，不在每列重複。

## GDK 命名與欄位原則

- 表格名稱使用清楚的英文 PascalCase，例如 `Module`、`AIStrategy`、`ActiveSkill`、`PassiveSkill`、`Skin`、`Emote`。
- `ID` 通常使用 `int`，需唯一；是否連續依專案需求。
- 資源欄使用 `string`，保存規格指定的資源 ID。
- 價格與貨幣類型分欄管理。
- 只有確定存在動態停用需求時才新增 `IsEnabled`。
- 全資料共用的 Duration、倍率或限制優先放入 Module。

## GDD／GDK 完成驗證

- 比對修改前後的二、三級標題、數值表、檔案大小與行數，確認沒有非預期遺失。
- 檢查 Markdown 表格欄數、圖片路徑、`details` 標籤、Mermaid 語法與版本號。
- GDK 驗證 A1 與表格／檔案名稱一致、每列欄位數一致、輸出欄位 metadata 完整、非輸出欄位 metadata 留空、資料型態只使用允許類型、ID 無重複、比例／負值／時間換算正確、Module 與專表沒有重複資料真源。
- 回報同步來源、衝突處理、備份位置、驗證結果與未驗證事項。
