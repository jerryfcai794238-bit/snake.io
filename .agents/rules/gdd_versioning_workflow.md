# GDD 版本控制與標記流程 (GDD Versioning & Tagging Workflow)

本文件規範重大更新時的文件版本控制、變更歷史折疊、以及行內版本標記的增刪規則。

## 1. 版本晉升與日期更新 (Version Bump)
- **首頁進版**：每次進行規格調整，必須於 GDD 首頁標頭更新 `文件版本` 與 `更新日期`。
- **後記進版**：同步更新文件最末尾的 `*Powered by Antigravity vX.X*` 標記。

## 2. 行內版本標記規範 (Inline Version Tags)
- **版本標記格式**：所有新增、修改的條目、表格行或段落，必須在尾端附上紙筆圖標與版本標記，格式為 `📝[vX.X]`（例如：`📝[v0.5]`）。
- **標題免標記**：以 `#`、`##` 或 `###` 開頭的各級標題，**一律不標記**版本號，保持目錄乾淨。
- **前版標記剔除 (Tag Stripping)**：當文件版本晉升（例如從 `v0.4` 進版至 `v0.5`）時，必須執行**歷史標記清理**：
  - **保留當前**：僅保留當前最新版本的行內標記（如 `📝[v0.5]`）。
  - **剔除前版**：將前一版本（如 `📝[v0.4]`）及更早版本的所有行內標記從內文中**徹底刪除/剔除**，使其融入基礎規格，避免文檔充斥雜亂的歷史標籤。

## 3. 變更紀錄折疊規範 (Changelog Collapsing)
- **第 2.2 節更新歷史**：
  - **當前版本**：使用 `<details open>` 標籤，預設展開當前最新版本（如 `v0.5`）的變更紀錄，並在 `<summary>` 右側加上 `📝[vX.X]` 標籤。
  - **歷史版本**：將所有舊版本（如 `v0.4`、`v0.3`）的 `<details open>` 修改為 `<details>`（預設折疊），並將標頭改為 `歷史更新`。

## 4. Mermaid 流程圖語法限制 (Mermaid Constraints)
- **禁止行內標記**：Mermaid 流程圖（如 Chapter 5.0 的介面跳轉圖）的節點名稱、箭頭連線與邏輯分支中，**嚴禁**出現 `📝[vX.X]` 標籤或包含中括號的字元。這會直接導致 Mermaid 編譯引擎崩潰。
- **語法保全**：Mermaid 圖表內部應保持乾淨，若節點名稱包含括號等特殊字元，必須使用雙引號將整個節點文字包裹起來（例如：`ID["節點 (說明)"]`）。
