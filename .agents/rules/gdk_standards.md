# GDK 遊戲資料表標準規範

本文件定義 GDK（Game Data Kit／遊戲 DataTable）的產表、欄位、拆表、數值與驗證標準。GDK 是供企劃維護、程式匯入的遊戲資料，不是資料庫 Schema。

## 1. 基本定位

- 依 GDD、參數表、美術需求、字串表與其他指定規格建立資料。
- 不自行加入 PK、Index、Auto-Inc、VARCHAR、UNSIGNED 等資料庫設計。
- 不虛構來源文件未定義的價格、ID、資源名稱、字串表編號、貨幣或狀態。
- 必要但未定義的欄位保持空白，並在完成回報列為待補資料。

## 2. 表格固定結構

每張表依序包含：

1. A1 表格名稱列
2. `輸出`
3. `名稱`
4. `資料型態`
5. `企劃名`
6. 實際資料列

規則：

- A1 必須填實際表格／檔案名稱，例如 `Module`、`ActiveSkill`。
- 不使用 `Item`、`Table` 等通用占位名稱。
- 每一資料列代表一筆可配置資料。
- 每列欄位數必須一致。

## 3. 輸出標記

- `B`：Client + Server 共用。
- `C`：僅 Client 使用。
- `S`：僅 Server 使用。
- 純企劃閱讀、描述、單位或備註欄位不輸出。
- 非輸出欄位在 `輸出`、`名稱`、`資料型態` 三列全部留空。
- 輸出欄位必須同時具有輸出標記、程式名稱與資料型態。

## 4. 資料型態

常用型態限定為：

- `int`
- `string`
- `bool`

原則上不使用 `float`：

- 小數時間改用整數秒或毫秒。
- 機率、倍率與速度修正使用百分比或萬分比整數。
- 布林狀態使用 `bool`，資料填 `true`／`false`。

## 5. 企劃欄位與字串表

- 中文名稱與描述屬企劃閱讀欄位，不直接輸出。
- 程式需要顯示文字時，新增對應字串表編號欄位。
- 欄位順序必須相鄰：
  - 名稱 → 名稱字串表編號
  - 描述 → 描述字串表編號
- 字串表編號欄位通常使用 `int`。
- 未提供字串表編號時保持空白，不自行編號。

## 6. 描述與單位

- 描述欄只說明效果與用途，不重複寫百分比、萬分比、秒、毫秒等單位。
- 單位統一放在最後的 `單位` 備註欄。
- 單位欄不輸出，因此不設定程式名稱與資料型態。
- 同一程式欄位不可混用秒與毫秒。
- 比例欄若統一採萬分比，負值也需換算，例如 `-25%` 寫為 `-2500`。

## 7. 拆表與資料真源

- `Module` 僅保存沒有獨立專表管理的全域參數。
- 技能、道具、AI、造型、貼圖等多筆同類資料應各自拆表。
- 所有資料只能有一個真源，專表與 Module 不得重複。
- 建立專表後，只移除真正重複的 Module 參數，不可整類刪除。
- 修改前應逐項確認：
  - 保留
  - 移除
  - 移轉
- 所有資料列共用的值應放入 Module，不在每列重複，例如統一顯示時間。

## 8. 表格設計原則

- 表格名稱使用清楚的英文 PascalCase，例如：
  - `Module`
  - `AIStrategy`
  - `ActiveSkill`
  - `PassiveSkill`
  - `Skin`
  - `Emote`
- `ID` 通常使用 `int`，需唯一；是否連續依專案需求。
- 資源欄使用 `string`，保存規格指定的資源 ID。
- 價格與貨幣類型分欄管理。
- 只有確定存在動態停用需求時才新增 `IsEnabled`。
- 全資料共用的 Duration、倍率或限制優先放入 Module。

## 9. 來源同步

產表前需確認相關來源：

- GDD 規則與參數章節
- 美術需求的造型、貼圖、Icon、Map、FX、SFX 清單
- 字串表
- 商店、價格、解鎖與成長規格

若來源互相衝突：

1. 停止擴大修改。
2. 列出衝突欄位與來源章節。
3. 等待使用者指定真源。

## 10. 驗證清單

- [ ] A1 與表格／檔案名稱一致。
- [ ] 每列欄位數一致。
- [ ] 輸出欄位具有輸出標記、程式名稱與資料型態。
- [ ] 非輸出欄位三列 metadata 全部留空。
- [ ] 資料型態只使用允許類型。
- [ ] ID 無重複。
- [ ] 品項數量與名稱符合來源文件。
- [ ] 比例、負值、時間換算正確。
- [ ] Module 與專表沒有重複資料真源。
- [ ] 未定義值保持空白，沒有自行補造資料。
- [ ] 字串表、資源 ID、價格、貨幣與解鎖狀態無衝突。
