# GDD 標準規範 (GDD Standards)

本文件定義 GDD 的排版、格式化、數學公式與數值設計的撰寫標準，確保規格文件具備實作級的精確度與高跨平台相容性。

## 1. 表格化優先原則 (Table-Driven Specs)
- **數值必表**：任何物理參數、冷卻時間、距離、機率、配額、屬性明細等，嚴禁使用散文段落描述，必須統一彙整至 Markdown 表格中。
- **邏輯必表**：狀態機切換（如碰撞矩陣）、技能效果對照、戰術道具覆蓋規則等，一律以表格呈現。
- **參數欄位規格**：數值參數表必須包含：`參數名稱`、`參數描述`、`預設數值/初始數值`、`滿級數值`（若有）、`每級增量`（若有）、`單位`。

## 2. 數值設計原則 (Numeric Design Standards)
- **去小數點化 (No Decimals)**：為了防範浮點數精度誤差及簡化運算，GDD 內所有參數一律採用**無小數點整數設計**：
  - **比例/機率**：一律換算為**萬分比 (X｜萬分比)**。例如 `50%` 寫為 `5000`，`1.35倍` 寫為 `13500`。
  - **時間/週期**：亞秒或帶有小數點的秒數，一律換算為**毫秒 (ms)**。例如 `2.5秒` 寫為 `2500ms`；整數秒可維持 `s`。
  - **物理距離/速度**：一律以 `px` 或 `px/s` 表示。

## 3. CJK LaTeX 渲染保全 (Math Block Compatibility)
- **渲染崩潰預防**：標準 Markdown/KaTeX 渲染器（如 VSCode、Notion、GitHub）在解析 LaTeX/KaTeX 數學公式區塊（即 `$$...$$` 或 `$...$`）時，若公式內部含有 **CJK 中文字元**，將會直接導致語法解析崩潰、無法顯示公式。
- **解決方案**：所有涉及中文字元或文字說明的數學公式，**嚴禁**使用 LaTeX 語法。必須改用**標準純文字程式碼區塊**（Code Block）進行排版。
  - *錯誤示範*：`$$ 升級金幣 = \text{基礎金幣} \times 1.15^{\text{當前等級}} $$`（導致崩潰）
  - *正確示範*：
    ```text
    升級所需金幣 = PASSIVE_UPGRADE_BASE_COST * (PASSIVE_UPGRADE_EXPONENT / 100) ^ 當前屬性等級
    ```

## 4. 漸進式架構 (Progressive Specs)
GDD 的主體章節架構應遵循從底層物理至上層策略的漸進邏輯：
1. **角色基礎屬性**：速度、吸附半徑、視野等基本變量。
2. **地圖與環境**：地圖寬高、地形限制、岩石碰撞、河流緩速區。
3. **食物與生成**：食物價值、安全生成、地形權重、補充投放、碎裂殘骸規則。
4. **復活與生命週期**：死亡判定、復活倒數行為限制、重生幽靈無敵。
5. **競技模式與 AI**：勝負條件、排行榜 HUD 顯示規則、電腦 AI 性格策略與切換。
6. **技能與道具**：衝刺與超載、主動漩渦、地圖道具堆疊與覆蓋邏輯。
7. **養成與經濟**：被動升級公式、商店定價、入場消耗。
8. **UI 與美術需求**：UI 介面跳轉流程圖（Mermaid）、介面佈局、2D 美術資源產出清單。
