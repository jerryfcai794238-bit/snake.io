# GDD 反向同步協議 (GDD Reverse Sync Policy)

為了確保文檔與代碼實現的一致性，必須定期執行反向同步。

## 1. 觸發時機
- 執行 `/gdd-versioning` 時。
- 使用者要求「核對規格」時。
- 發現 GDD 參數與代碼實際表現不符時。

## 2. 審核對象
必須檢查以下文件中的數值：
- `src/constants.js`: 全域配置與道具參數。
- `src/game.js`: 邏輯觸發門檻（如導引機制、熱點時間）。
- `src/snake.js`: 蛇的基礎物理屬性。

## 3. 同步標準
- **以代碼為準**：若代碼已經通過測試並運行良好，但 GDD 描述不同，應將 GDD 更新為代碼中的實際數值。
- **表格優先**：所有同步回來的參數必須以 Markdown 表格形式呈現，禁止使用模糊的散文描述。

## 4. 驗證
- 同步後應執行 `/gap-audit` 以確保無殘留衝突。
